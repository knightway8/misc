Reusable installation reference

Fedora 44 + NVIDIA RTX 4060

A cautious, repeatable way to move an Alienware Aurora R16 from Mesa NVK/Zink to NVIDIA’s packaged driver stack while preserving Secure Boot.

What this guide is—and is not

The GNOME report string zink … NVK AD107 means the system is using Mesa’s accelerated NVK/Zink graphics stack. Testing NVIDIA’s packaged stack is a reasonable A/B test for the freezes, but it is not a promise that every freeze will disappear.

Designed for Fedora 44 Workstation, traditional DNF installation, RTX 4060/Ada.
Not designed for Silverblue, Kinoite, Bazzite, or another rpm-ostree/Atomic system.
Generated August 19, 2026. Re-check Fedora/RPM Fusion guidance on a later release.
Run one section at a time. Read the expected result before proceeding. These buttons copy text only; this page never runs shell commands.
  • Back up anything important and save open work.
  • Keep Fedora’s older kernel entry until the new driver is verified.
  • Use RPM Fusion packages—never NVIDIA’s standalone .run installer.
  • Do not mix RPM Fusion drivers with NVIDIA CUDA-repository driver packages.

If the immediately preceding boot ended in a freeze and hard reset, save its relevant kernel messages. If another normal reboot happened afterward, use journalctl --list-boots to find the right boot index. 

sudo journalctl -k -b -1 --no-pager | grep -Ei 'nouveau|nova|nvk|nvidia|NVRM|Xid|drm|gpu|fifo|hang|fault|timeout|gsp'

Record the currently loaded graphics driver:

lspci -nnk -d 10de:
lsmod | grep -E '^(nouveau|nova_core|nvidia)\b'

Rebooting here ensures the NVIDIA module is built for the kernel you are actually running—not the older kernel that happened to be active during an update. 

sudo dnf upgrade --refresh

When the update completes normally:

sudo reboot

Fedora does not ship NVIDIA’s driver stack in its base repositories. RPM Fusion packages it for Fedora’s normal update and kernel-module workflow. 

sudo dnf install \
  https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm \
  https://mirrors.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm
sudo dnf install akmods mokutil openssl
mokutil --sb-state

If it reports “SecureBoot enabled”

Generate the local akmods signing key first, then request its enrollment. The password requested by mokutil is a temporary, one-time MOK password—not necessarily your Linux password. 

sudo kmodgenca -a
sudo mokutil --import /etc/pki/akmods/certs/public_key.der
Do not reboot yet. Install and build the NVIDIA module in the next sections so it is signed with this key before the MOK-enrollment reboot.

If it reports “SecureBoot disabled”

Skip key generation and MOK enrollment. Continue with the driver installation.

akmod-nvidia is the correct current package for an RTX 4060. Do not select a legacy branch or manually force akmod-nvidia-open. Current packaging chooses the appropriate NVIDIA kernel-module flavor.

The CUDA subpackage is optional for display output, but it supplies compute components and nvidia-smi, which is useful for verification. 

sudo dnf install akmod-nvidia xorg-x11-drv-nvidia-cuda

Build the module now. Let this command finish and return to the prompt; do not interrupt it or reboot early. 

sudo akmods --force

Confirm that the built module exists:

modinfo -F version nvidia
modinfo -F signer nvidia
Stop before rebooting if modinfo cannot find NVIDIA. If Secure Boot is enabled, also stop if the signer is blank. Open the troubleshooting section below rather than guessing.

A manual dracut --force is intentionally omitted. RPM Fusion’s packages handle the required driver configuration, initramfs work, and Nouveau/Nova blacklisting during normal installation. 

sudo reboot

Only when Secure Boot is enabled

  1. Press a key when the blue MOK screen appears.
  2. Select Enroll MOK.
  3. Select Continue, then Yes.
  4. Enter the one-time password created earlier. No characters may appear while typing.
  5. Select Reboot.

If Secure Boot is disabled, Fedora should simply reboot normally.

lspci -nnk -d 10de:
lsmod | grep '^nvidia'
nvidia-smi
Expected: lspci reports Kernel driver in use: nvidia, several NVIDIA modules appear, and nvidia-smi displays the RTX 4060 and driver version.

GNOME’s System Details should also stop describing the renderer as NVK/Zink. Use the machine normally and repeat the workloads that preceded the freezes.

Troubleshooting: build, signing, or another freeze

If the module build failed

sudo journalctl -u akmods --no-pager -b

Confirm Fedora was rebooted after its last kernel update and that the running kernel has matching development files: 

uname -r
rpm -q kernel-devel-$(uname -r)

If the matching package is missing:

sudo dnf install kernel-devel-$(uname -r)
sudo akmods --force

If Secure Boot is enabled but the signer is blank

Confirm the key file exists and rebuild after generating it: 

sudo kmodgenca -a
sudo mokutil --import /etc/pki/akmods/certs/public_key.der
sudo akmods --force --rebuild
modinfo -F signer nvidia

Reboot only after the signer is non-empty, then complete the blue MOK enrollment screen.

If the computer freezes again

After the forced restart, inspect the affected boot. NVIDIA faults often appear as NVRM: Xid; PCIe, timeout, and GSP messages are also useful. 

sudo journalctl -k -b -1 --no-pager | grep -Ei 'NVRM|Xid|nvidia|drm|gpu|pcie|hang|fault|timeout|gsp'
  • Try the previous Fedora kernel once from GRUB to test for a kernel regression.
  • If both NVK and NVIDIA stacks hard-freeze, run Dell’s F12/ePSA diagnostics and a memory test.
  • Do not make nomodeset a permanent “fix”; it disables normal graphics modesetting.
  • Do not randomly add old Xorg, GDM, DRM-modeset, or blacklist instructions from older guides.

When Pop!_OS becomes a reasonable Plan B

If the correctly loaded NVIDIA stack still freezes, testing the Pop!_OS 24.04 NVIDIA live image is reasonable. Use its demo mode before installing. Remember that current Pop uses the COSMIC Wayland desktop and System76 instructs users to disable Secure Boot.
